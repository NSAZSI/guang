## 四、步骤 6：AI 摘要三条路径

| 路径 | 结果 | 关键断言 |
|---|---|---|
| 无密钥（规则小编） | ✅ | AiStatus=Fallback；摘要 ≤80 字；标签 ≥3 且真实并入 Tags/NewsTags；详情页标注"规则生成摘要/未配置 AI 密钥"；点击 AI 标签 → 列表页精确筛出该新闻 |
| 有密钥（OpenAI 兼容 mock） | ✅ | 详情页先显示"生成中"→ 30s 内 Done；AI 标识；标签合并；"重新生成"换一版；**mock 故意用 ```json 代码块包裹返回，验证解析容错** |
| 错误密钥（故障演练） | ✅ | 发布接口照常 200；重试 1 次后 Failed + 规则兜底摘要；前端诚实标注"AI 服务暂不可用"；Serilog 警告：`[WRN] AI 摘要生成失败（新闻#43），已降级为规则摘要，主流程不受影响` |

架构要点：`IAiSummaryService` 抽象 + Channel 后台队列（BackgroundService 单读者顺序消费，避免 SQLite 写竞争），发布接口只投递任务绝不阻塞；密钥仅从配置/环境变量读取。
后台编辑页"重新生成"按钮 UI 实测：状态标签 生成中 → 规则生成 流转正常（final.spec，admin-ai-regen.png）。
密钥安全：工作区 + **Git 全历史**扫描真实密钥模式（sk-…/AKIA…）命中 **0**；库内密码均为 PBKDF2 哈希（AQAAAA… 格式），无明文。

**过程中发现并修复的真实部署 bug**：appsettings.json 硬编码 `"Urls"` 会覆盖 `ASPNETCORE_URLS` 环境变量（WebApplication 配置优先级），导致 systemd/keepalive 的端口注入失效。已移除该配置项，修复后生产进程精确绑定 127.0.0.1:5000（ss 核实）。

本地环境差异（如实注明）：容器基础设施占用 0.0.0.0:80，本地 nginx 验证绑定 127.0.0.1:80（交付配置为标准 `listen 80`）；容器无 systemd，用 keepalive.sh 等效验证 Restart 语义，systemd unit 文件已按规范写好待服务器使用。
